I am designing this project to work as a 100% autonomous, self-evolving, self-growing, self-learning digital brain and unified AI agent closely imitating to a human brain or human being to do anything and everything on 2D screen(computer and/or mobile) and 3D screen in physical world running inside a humanoid robot as core planner sharing same unified memory system. It is designed based on 4 concepts: Proactive learning, Reactive learning, Proactive response and reactive response and some existing machine learning concepts. Most concepts are already integrated in different projects and so I am trying to merge different components and fixing bugs and adding missing components etc. Basically, the final goal of the full project is to run as a 100% autonomous AI agent along with a digital brain which can train itself continuously for ever from internet on it's own and I don't have to replace models every few months. In other words, same AI model should be able to learn and improve on it's own by accessing file system, code bases and internet access to keep upto date and proactively contacting me from time to time. Finally, it is most important to note that the digital brain is NOT the AI model since I might use multiple AI models if required, but the core brain should be a "Single Vector Database" or "Set of vector databases" working together as a whole which will contain the series of "semantic signatures" of TEXT and VISION memories to refer with each other in cross modal manner to load based on context and this database will keep growing for ever with an upper limit of memory counts set in the settings of TEXT RAG and VISION RAG memory settings.

6 Core principles or concepts to build: 
#########################################

These 6 are the core concepts which can have multiple sub branches on its own.

1.Proactive learning: It will grow and learn via self-chat and re-enforcement learning and interacting to the web via web browser and interacting with computer, file system via OS Agent and continue to learn via RAG and LORA training. So before every prompt relevant memories from RAG and relevant LORA modules from LORA brain will be embedded through semantic vector database system. Same way after every AI reply relevant memories will be updated to RAG and relevant LORA modules will be strengthened. If no relevant LORA modules are available, then new modules will be created. It will happen both for text and vision based memories. All proactive learning will happen based on user inactivity from the time the last prompt sent by the user and this value can be set in the GUI as 10 min, 20 minutes and so on after which learning will start and continue for ever based on active missions in memory. This will be like active thinking process how human beings keep thinking and working through out the day from internet or from outside environment to work towards mission.

2.Reactive learning: This will happen during each user interaction where the user will guide in real time during every prompt. Everything else will happen same as proactive learning, but here user will explicitly guide the AI model what to learn and what not to learn. This is how human beings learn via direct interaction with other human beings or teachers or other people.

3.Proactive Reply: The system will have a sophisticated timer  based system based on which the AI can contact the user from time to time through out the day based on the user inactivity and user settings. This will be equivalent to how human beings send text messages or make phone calls from their end.

4.Reactive Reply: This is standard user prompt and response which will get highest priority and all background learning and processing will temporarily stop if the user manually sends a prompt just like human beings stop thinking or working and attend to a phone call if someone makes a phone call.

5.Active Mission Tracker: This concept is aiming to keep track of one or more active tasks or missions while conversations. Especially, it is the most important component of any type of agents whether browsing agent, coding agent or FULL computer agent in which the AI will save the  active MISSION or Active Full Task inside a JSON file along with a series of sub-tasks to complete in sequence in order to achieve the MISSION or Full Task and then, it will continue to follow that series of sub-tasks. The exact same concept and may be even code will be used in Android app, desktop app and humanoid robot as well for long running tasks or infinitely running tasks. I have a basic module to be integrated, but not fully tested.

6.Emergency Loop breaker: This is the second and most important missing piece of the project in which a robust post processing will be in ACTIVE MONITORING mode always to process each reply of AI before putting the reply into action for agentic tasks or before giving it back to the user. It can be called as a "Mental health Monitoring System " or "Self-awareness wake up call" in which a dedicated agent will be silently monitoring each AI reply and compare it with last 3 rolling window context memory and if 10% to 20% of tokens or phrases are exactly the same compared to any of it's last 3 replies, then, the system will trigger the wake up call with a unique SYSTEM PROMPT to inform the AI model that it is falling into loops and ask it to break the pattern with varied responses using unique words, phrases, varied reply length and so on and continue to discard it's replies until the agent fully wakes up and becomes self-aware. It is based on a concept applicable to human beings as well when a human being feels sleepy, then it may not pay attention to details and may start repeating same things and so the neighbour sitting next to him sees it and wakes him up. But most important that it must not generate false positives by discarding genuine replies and so I have kept this for integration at the end when most powerful and long running AI agents will be active. I mean this should be only in ACTIVE MONITORING mode and should be triggered rarely ONLY if genuine loops or patterns are found and must not interfere with correct and useful AI replies. This will also be used in Android app, desktop app and humanoid robot as well for long running tasks or infinitely running tasks. For this also, I have a basic module to be integrated, but not fully tested.

Existing machine learning concepts to use:
###########################################
1.Multi Unique System Prompts: In LLMs, SYSTEM PROMPT plays the crucial role for guiding the LLM behaviour and so the whole AI system will use unique and multiple system prompts to complement each other so that any AI agent will never get stuck in infinite loops or false learning patterns. Especially, the "Master Agent" will use a TWIN AGENT SYSTEM to guide the main agent in case if it falls into loops by carefully analysing context memory and comparing it with the reply of the Agent by unique wake up call SYSTEM prompt to vary the reply content and reply lengths etc.

2.Variable Random temperature: Temperature plays a crucial role in guiding the AI model behaviour and so all integrated AI agents will use random range bound temperatures to keep some level of randomness while still guiding the model towards the GOAL or ACTIVE MISSIONS stored in memory. So based on AI agent type, we may use a different temperature.

3.Brain like TEXT RAG Memory: The full AI system will use brain like RAG system which will continuously be used to retrieve relevant memories just before sending user prompt or system prompt and same RAG memory will be continuously updated after each AI reply just like how human brain works and the RAG memory will work both for personal memories and professional memories built from Agentic tasks. It will always give priority to latest similar memory based on timestamps while giving the history of similar memories or knowledge evolution. Currently, the TEXT RAG is categorised as "USER" and "ACTION". "USER" associated memories which are created by direct interaction with user must be given high priority where as "ACTION" based memories where the AI has learnt on it's own can be given a little less priority to avoid piling up wrong memories and not allowing the AI to bad memories to degrade performance. Only strong factual based findings should be given high priority even though all memories will be saved for reference and degraded and compressed over time based on usage how human brains work if the memory storage reaches very close to the allowed limit set in TEXT RAG settings.

4.Brain like VISION RAG Memory:: The same TEXT RAG memory like system will be used for VISION RAG for cross modal learning which means just before sending user prompt relevant memories will be retrieved and fed to the AI model irrespective of whether the user prompt contains image or not. Same way if the user attaches any image or if the AI is performing computer action or browser actions, then after every step the screenshots will be stored as vector based memories in VISION RAG very close to TEXT RAG what is already integrated. But VISION RAG will be multimodal. The memory retrieval during user prompt will always give high priority to latest similar memory based on timestamps while giving the history of similar memories or knowledge evolution. For example, if the word elephant appears in user prompt, then it will refer to the last image of an elephant and the text associated with that elephant and additional images associated with that elephant automatically  as first priority based on timestamps how human brains fire latest experiences automatically along with strongly referred memories associated with that image or event or query. The vision memories should be stronger and weaker asymptotically based on frequency of usage and specific key words which involve strong emotions like "never, always, remember, must, important, critical, love, hate, like etc" This much words without case sensitivity are enough to build strong memories if used properly. These key words must be reserved and used ONLY for "USER" based memories and not for "ACTION" based memories. 

5.Multiple model use: The AI system might use 2 or more AI models dynamically like how left hemisphere  and right hemisphere of brain works or how different parts of the brain work together cooperatively. This is one key and important aspect of the project considering the fact that every AI model has it's own strength and weaknesses and they fall into never ending loops or patterns after a certain period. So switching the models alternatively after certain number of prompts or after each prompt or simply randomly can be the best and natural way of breaking from loops. For now, my first priority is "Gemma 3 27B" as single AI model and my second priority is "Qwen 3 VL 30B". "Gemma 3 27B" seems to be sufficient for text based tasks with few limitations, but  "Qwen 3 VL 30B" is primarily tested and used for vision tasks. Both are vision models and so either we will use one model or both models or may be multiple models if possible and easy to use since our core brain will be "Vector Database" means a collection of TEXT and VISION RAG Memories containing all details and the core brain is NOT tied to a single model. So our first priority model will be "Gemma 3 27B" and second priority model will be "Qwen 3 VL 30B"  and so any coding should not be biased or hardcoded for either of the model. Because everything must revolve around one thing which is "TRUE GENERALISATION AND INFINITE 100% AUTONOMOUS LEARNING" based on which the "DIGITAL BRAIN" must work. 5 critical components of individual AI Agents:
#########################################
The full AI project may have multiple AI agents running simultaneously in parallel co-ordinating with each other and each AI agent must have either one or more of the below critical components. Some AI agents may have all of the below 5 components.

1.Asynchronous timer: Each AI agent will have a dedicated asynchronous timer tied with a dedicated JSON file to monitor independent of each other so that it can run independently without affecting other AI agents. For example, an "Input AI Agent" will continuously run and track the inputs from outside of the system whether it comes from the user or from environment or other AI agent etc tracking a dedicated JSON file. Same way an "Output AI Agent" will track all outputs of the AI Agents before execution or before sending the reply back to the main interface or user interface. There can be numerous such agents in between with clear entry and exit points.

2.Task Breaker: Every AI agent which deals with loops for completing complex tasks must first convert the user prompt or outside input into a "Active Full Task" which will be a brief summary of the prompt understandable by the AI explaining what the user wants and what AI understands. Then, break that task into a series of sub-tasks with numbers and that full data must be stored inside a dedicated JSON file as long as the Task is ongoing and each sub-task will be fed sequentially one by one to the AI while keeping track of the full task and a real Time understanding of what AI has done last time and what it is doing now.

3.Loop Breaker: This will be special SYSTEM prompt and a dedicated which will continuous monitor the last 3 prompts and replies of the AI and track if the AI is entering into loops by comparing % of tokens means % of phrases or sequence of words if the AI is repeating the same sequence of words like more than 10% of the words in more than 1 reply, then it will trigger an emergency loop breaker prompt which is explained above.


4.Rolling window context: Each AI agent must save at least a 3 rolling context memory of last 3 prompts and replies of the AI in a text or JSON file which must be updated after every AI reply and must be fed in every prompt.


5.Infinite RAG memory: Each AI agent must have access to a near Infinite TEXT RAG and VISION RAG memories of whatever they have learnt or encountered in the past. So precisely 5 to 10 relevant memories will be fed to each AI agent and after each AI reply also these memories will be updated continuously for ever.
